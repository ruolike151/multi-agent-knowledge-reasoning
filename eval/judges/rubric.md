# 答案评分 rubric（0 / 1 / 2）

你拿到的输入有三段：`[问题]`、`[标准答案与 gold 引用]`、`[候选答案]`，以及 `[原文摘录]`。
只按下面的标准打分，不参考候选答案的措辞是否漂亮。

## 2 分：正确

- 候选答案的**关键事实**与标准答案一致（数字、主体、时间、口径都要对得上）；
- 允许表述不同（同义词、换语序、更简洁），不允许**事实新增**：多出来的具体数字、
  子公司名、日期必须能在原文摘录里找到；
- 若问题要求综合多份文档，必须覆盖标准答案里的**每一个**要点。

## 1 分：部分正确

- 覆盖了部分要点，但缺少关键要点；或
- 结论正确但**口径错误**（如把"营业收入"答成"营业利润"、把年度数据答成季度数据）；
- 或结论正确但没有给出任何可核对的依据（原文摘录里找不到支撑）。

## 0 分：错误

- 关键数字/主体/年度任一错误；
- 答案与问题无关，或答非所问；
- 存在**原文摘录无法支撑的具体断言**（即幻觉）；
- 问题在知识库中无答案时**未明确拒答**，而是编造了一个具体答案。

## 边界情况的固定判法（避免同一份答案两次打分不同）

| 情况 | 判法 |
|---|---|
| 候选答案比标准答案更详细，但每个新增事实都能在原文摘录里找到 | 2 分 |
| 候选答案漏掉标准答案中的次要限定条件（如"母公司口径"） | 1 分 |
| 候选答案给出正确数字但单位写错（亿元/万元） | 1 分 |
| 候选答案同时给出正确与错误两个数字 | 0 分 |
| 候选答案只说"无法从知识库确定"，而问题确实无答案 | 2 分 |
| 候选答案只说"无法从知识库确定"，而问题在知识库中有答案 | 0 分 |
| 候选答案包含"根据某年报告"等不可核对的笼统表述，但事实正确 | 不影响分数 |

## 输出

只输出 JSON：`{"score": 0|1|2, "supported": true|false, "reason": "一句话理由"}`。
`reason` 必须引用候选答案里的具体内容，不要写"整体不错"这类无法复核的理由。
