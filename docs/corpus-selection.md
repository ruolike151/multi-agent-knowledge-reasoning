## 2. 渠道与接口

全部取自**巨潮资讯网**（`www.cninfo.com.cn`，交易所指定的信息披露平台）：

| 步骤 | 接口 | 说明 |
|---|---|---|
| 换 `orgId` | `POST /new/information/topSearch/query` | 参数 `keyWord=<股票代码>`，取返回项的 `orgId` |
| 列公告 | `POST /new/hisAnnouncement/query` | `stock=<code>,<orgId>` + `column=sse/szse` + `seDate`；年报用 `category=category_ndbg_szsh`，公告用空 category 拉全量 |
| 下 PDF | `https://static.cninfo.com.cn/<adjunctUrl>` | 需要 `User-Agent` + `Referer` |

踩到的三个坑（已写进脚本注释，避免下次重踩）：

1. **接口忽略 `pageSize`**，固定每页 30 条；且第一页的 `totalAnnouncement` 可能是 `0`，
   必须取各页累计最大值来翻页，否则只能拿到第一页（会让公告候选几乎全空）。
2. **`searchkey` 关键词检索不可用**（搜「投资者关系活动记录表」返回 0 条），
   只能拉全量再按标题正则匹配。
3. **`static.cninfo.com.cn` 的 HTTPS 在部分 Windows 环境下 schannel 握手失败**
   （`Invoke-WebRequest` / `curl.exe` 报 `SEC_E_NO_CREDENTIALS`），因此 PDF 一律用
   `requests`（仓库 `.venv` 内已装）下载。

## 3. 公告筛选规则

设计文档要求公告**与年报同期、含明确金额或产能数字、且提及产业链上下游实体**，
五类各一份。落地方案：

1. **归桶**：拉 2025-01-01 ~ 2026-12-31 的全量公告（与 2024/2025 年报的披露期同期），按
   关键词归入 5 类；统一排除制度类与第三方文件（`管理制度 / 管理办法 / 决策制度 /
   专项报告 / 审计报告 / 核查意见 / 关注公告` 等），它们不是事件型事实。
2. **指派**：5 种类型分给 5 家**不同**公司，候选越稀缺的类型越先分配（回溯匹配）。
3. **打分选文**：每个槽位按标题时间倒序逐条试下载（最多 4 条），按下面的分值留下最高分：

   | 分值 | 判据 |
   |---|---|
   | 3 | 含金额/产能数字 **且** 点名本批其他 4 家公司之一 |
   | 2 | 含金额/产能数字 **且** 出现公司实体（`…有限公司`） |
   | 1 | 只满足金额/实体之一 |
   | 0 | 都不满足（该候选删除，继续下一条） |

   `mentions_peers` / `entity_names` / `has_amount` / `filter_score` / `filter_relaxed`
   都写进了 `data/manifest.json`，可逐条复核。

## 4. 已知取舍

- **投资者关系类只能选到「参加投资者集体接待日暨业绩说明会」的公告。** 5 家公司在
  2024-01-01 ~ 2026-12-31 窗口内**都没有发布**正式的《投资者关系活动记录表》
  （已逐家核对标题：只有「召开/参加业绩说明会」通知），因此 5 家都无同行实体可对照。
  该类单独放宽为「正文出现公司实体即通过」，并在 manifest 标记 `filter_relaxed: true`，
  不做静默处理。若后续需要更厚实的调研纪要，可换同环节公司或扩窗口后重跑脚本。
- **没有一份公告同时点名本批其他 4 家公司**（即无 3 分候选）。跨文档链接主要靠年报
  （年报会互相点名供应商/客户/同业产能），公告提供的是订单、扩产、关联方与预期这几类
  年报查不到的事件型事实，与设计文档 §8.1 的定位一致。
- `mentions_peers` 只比对**本批 5 家的简称**，因此上市公司的全称（如「隆基绿能科技股份有限公司」）
  同样能命中；同名次实体（如「通威太阳能」为自己的子公司）记录在 `entity_names` 里。
